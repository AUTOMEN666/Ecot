# Stack Bowls在线协议

DeepSeek负责生成Subtask，π0.5负责动作。原Instruction固定为：
Stack the three bowls together.

## 文本来源

ACTIVE_EXPANDED_CATALOG.json含真实Stack Bowls100投影中297条不同原句，
覆盖44674有效训练起点，保持文本原文/频次，不改写或添加组合句。
候选库不包含测试布局、未来顺序、示教帧映射或成功真值。

API公开回答只能是：

~~~
宿主查表得到原文Subtask，只向策略拼接Instruction与该文本。
没有语义修复/重试、旧文本回退或其它模型兜底。

## 因果观测和历史

每执行8动作，从真实当前观测重新生成：
1. 当前主/左腕/右腕三张640×480 RGB和实际State14。
2. 本回合10Hz源帧floor(2.5*k)：0、2、5、7、10…；只用严格过去主图。
3. 完整过去前缀均匀取至多93点；超过时取i*(N-1)//92，保留首末，再接当前三图，总计最多96图。
4. 每图对应实际State14、帧/时间/SHA；State顺序左6关节＋左夹爪＋右6关节＋右夹爪。
5. 完整已确认执行历史：ID/原文、观测帧、实际执行动作范围。

首帧没有过去图片/历史。最后重规划792帧，含99条过去执行记录，终局最多100条。
失败请求、未执行提议、跨回合数据不入历史。历史/ACK RPC不修改策略RNG或当前观测。
策略只收到当下三图、State14和文本；不收到生成器的图像/执行历史。
仿真对象名/位姿仅本地冻结审计使用，不发送给DeepSeek或策略。
无未来图、未来真实动作、完整示教或场景真值进入在线生成。

## 叠碗连续性

未完成目标持续服务同一物理碗与支撑碗/栈；每8步查询不等于更换目标。
位置词绑定选择时的实例，碗移动后不能转指另一个当前最右碗。

- 仅抓取：同一碗明确抓稳且离开支撑，才转入放置。
- 仅放置/叠放：目标上形成支撑/嵌套且已释放、未滑落，才算完成。
- 抓取并叠放：两阶段都完成；撤退/回臂不是新抓取。
- 两碗栈不等于三碗完成；不拆解有效栈；滑落/错放不记完成。
- 三碗已叠好后选择受支持的释放/撤臂目标，保持栈稳定；SDK原始成功还包含机器人回位，不要因为尚未终止就重新抓碗。
- 遮挡、经过8动作或旧文本都不能证明完成，明确视觉反证允许纠错。

这是Prompt和已执行历史提供的约束，不是程序取得接触/完成真值。
不宣称保证LLM识别、实例跟踪或子任务完成判断正确；须实际闭环验证。
模型不决定回合终止，成功/终止始终使用原SDK。

## 调用与冻结

沿用源分支deepseek-v4-1-flash-261017，temperature0，thinking enabled/high，
max_tokens65536，JSON object。HTTP600秒、整体生成预算1850秒、最多3次相同请求；
仅原有瞬时网络/429/5xx/空内容长度截断重试。RPC/ping等待2100秒。
非法ID导致工程中断，不能静默不加ECoT或当成正常SDK失败。

阻塞等待前后核验机器人、任务三碗、所有其它当前对象及250Hz物理时钟不变。
每个25Hz动作恰好推进10物理步；动作间及历史/生成/ACK等待推进0步。
每回合新策略进程、新日志，reset历史和noise42；验收后不追加其它回合。
