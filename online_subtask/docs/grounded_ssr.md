## What changed and why

The earlier observer could stop the entire case because one unrelated object was
uncertain, copy an old query timestamp into a new image-evidence array, or emit a
close/lift instruction while the object was still outside the jaws. This revision
keeps observation, goal admission and immediate action prerequisites explicit.

The first API call returns current objects, basket visibility/contents and both
arms' actual grasp relations. Identity/category/descriptor uncertainty is local.
An unknown held object is never hidden to permit a table pickup; unknown contents
only block the affected basket. The model does not generate historical frame
arrays. The host binds each report to its actual current capture and accumulates
two consecutive clear released-container observations. Occlusion, drops and
regrasps break that confirmation. Past selected/executed text proves no completion.

The same physical object and target basket retain the same ID across phases.
Another similar instance cannot complete it. Explicit current visual corrections
may reopen a goal decision; the selector still chooses an allowed exact ID. A
generic descriptor is not a permanent global category assignment. Same-wording
instances require an actually held object or a unique clear current interaction
to disambiguate them; the host does not choose by array order or guess a target.
Verified post-placement withdrawal/settling can retain the last goal without
claiming SDK success or asking for another pickup.

The second call generates only `subtask_id`, public `reasoning` and
`action.summary`. Exact real training examples guide language style, while the
current facts constrain feasible intent over the next8–16 actions. Summary names
an immediate action and its acting arm; Reasoning explains the current constraint
and useful next adjustment. A target merely visible in a wrist image is not yet
enclosed. Closing needs alignment between opposing fingers; lifting needs a
supported grasp; release needs the correct basket and current placement readiness.
Both fields must agree on object, arm, basket and action phase. Current facts and
intended transitions remain distinct.

An identifiable object between closing jaws need not yet be securely supported.
A narrow exception preserves the already locked goal when two adjacent actual
visual reports show the same clear table target enclosed by the same clearly
visible, transitioning, closing gripper. Exactly one hand may report uncertain
holding; the other must be clear and empty. Separate current/previous/remembered
held material blocks this exception. Only Close/Hold are admitted for the closing
hand, and only Hold for the other hand. Neither the observation nor its unknown
holding state is rewritten. Lifting, carrying and releasing remain prohibited.
At most two8-action uncertainty windows are available for that same closure;
empty/unknown label oscillations and the opposite hand's approach do not reset
the budget. Actual secured holding, a genuine same-hand reopen/reapproach or a
changed/completed goal can end that closure. Repeated unconfirmed closure stops.

Unsupported schema/ID/goal/phase assertions stop before inference. There is no
semantic redraw, output repair or replacement text. Natural phrases such as
"right open gripper" are recognized as an explicit actor without editing them.
The text checks are conservative counterexample checks, not a perception or
English semantic oracle. Independent visual quality review is still required.

`evaluation/support/weights_contract.py`. Do not relabel a Subtask-only or dropout

## Evaluation boundaries

Development episode201 diagnosed earlier failures. Episodes202/203 were fixed
before the first parallel iteration and excluded from the style-reference bank,
but subsequent format/consistency failures informed revisions. They are now
regression trajectories, not untouched prompt holdouts. No GT or future image/action
was used to choose object/category/arm/basket decisions. Same-frame
expert replay exposes only the current/past observations and previously generated
Subtasks. Expert motion was not controlled by those labels, so it is never called
a real policy injection or ACK. GT and future16-frame reference windows are read
only by the independent evaluator/renderer. Alternative legal object/basket order
is not automatically wrong; exact text agreement is not semantic accuracy.
These trajectories belong to the original training corpus: "held out" here
means reserved from this prompt iteration/reference bank, not unseen by EMA19566.

Evaluate present facts and short-term intent separately. Critical early
close/lift/release, wrong object/arm/basket, unresolved ambiguity and repeated
unproductive holds must remain visible. Full source video is not full annotation.
